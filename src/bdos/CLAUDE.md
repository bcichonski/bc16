# bdos (disk OS, utilities, apps, B libraries)

Reference: `docs/05-bdos.md` covers the memory map, the BFS disk format, the bdio API and
error codes, the shell and the utilities. `bdos.md` holds the short notes.

Everything here is B source except `boot.basm`. Each program's `.genb`, `.basm`, `.btap`
and `.sector(s)` are generated by the build and committed.

## Build (from `src/`)

```bash
./bcc bdos/ls                                     # one program
./buildos                                         # bcOS + boot.basm + bdos.b (shell + bdio)
./buildtools                                      # ls cp format rm cha cat
./buildapps                                       # helloworld texted
./makedisc                                        # *.btap -> *.sector(s) -> fresh os.bdd
python3 bc64.py bc81asmc/bcOS/bcos_v1_2_0.b81     # boot; enter "os.bdd" for disk A, then e.g. "ls -a"
```

## Structure

- **Boot:** `boot.basm` (`.org 0x0e00`) reads sectors `0x20..0xbf` to `0x0f00` and jumps
  there.
- **`bdos.b`:** the shell `main`. It writes `bdio_call` into bcOS slot `0x37`, then reads a
  command line into `0x0dd2` and runs `NAME.PRG` from the disk at `0x6000`. It `#include`s
  `bdio.b`, the actual I/O layer.
- **User programs** reach bdio only through `bdosh.b`. Its wrappers set `F=0x37`,
  `A=call`, `CSCI=param1`, `DSDI=param2` and call `os_metacall`. `bdio_call` in `bdio.b`
  dispatches on `A`.
- **`bdioh.b`** holds every shared constant: FDD commands, catalog and descriptor offsets,
  error codes, bdio call numbers and **fixed memory addresses**.
- **Libraries:** `std.b`, `stdio.b`, `strings.b`, `stdmem.b`, `bdostools.b`.
- **Programs:** `ls`, `cp`, `rm`, `cat`, `cha`, `format`, `helloworld`, `texted`.
  `calc.b`, `theodore.b`, `fddtest.b` and `debug.b` aren't built onto the disc.

## Rules

- **New bdio call:**
  1. add the number in `bdioh.b`;
  2. add a branch in `bdio_call` (`bdio.b`);
  3. add a wrapper in `bdosh.b`;
  4. document it in `docs/05-bdos.md`.

  Shell-only functions (`bdio_execute`, `bdio_ffindfile`, …) are deliberately left out of
  the dispatcher.
- **Memory map:**
  - `bdos.b` is `#code 0x0f00` and must end below the file buffers at `BDIO_FDESCBUF_ADDR`
    (`0x5d00`). Check the end address in the `.btap` preamble after a build.
  - User programs are `#code 0x6000` (`BDIO_USERMEM`). Moving that means changing every
    program's `#code` line.
  - The `#heap` value is chosen per program.
- **New or larger program on the disc:**
  1. add it to `buildtools`/`buildapps`;
  2. add it to `makedisc` (both the `btap2bin` and the `importsector` lines) at a free start
     track;
  3. add a 16-byte entry to the hand-made catalog `src/fcat0800.sector`: number, track,
     sector, length in sectors, attributes, 8+3 space-padded name.

  Executables need the X attribute (`0x04`); system files also carry S (`0x80`).
- Programs get their arguments by parsing the shell buffer at `BDIO_CMDPROMPTADDR`
  (`0x0dd2`), typically `upstring(...)` then `strnextword(...)`. They return to the shell
  with a normal function return.
- File names in the bdio API use the 11-character catalog form (`"LS      PRG"`).
  `bdio_fnormalize` (`bdostools.b`) converts from `name.ext`.
- B quirks used throughout these sources:
  - put each comparison in parentheses (`(a > 0) && (b = 1)`);
  - `=` is equality and `<-` is assignment;
  - assign a `result` variable and `return` it at the end instead of returning early.
