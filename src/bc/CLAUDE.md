# Compiler (bc, B language)

Reference: `docs/03-compiler.md` covers the language, operators and libraries.
`history.txt` records the code-size optimisation history and `bugs.txt` the known bugs.

## Commands

```bash
cd src && python3 bc/bc.py bdos/ls.b              # -> bdos/ls.basm, prints one summary line
cd src && python3 bc/bc.py --verbose bdos/ls.b    # same, plus the trace and bdos/ls.genb (preprocessed source)
cd src && ./bcc bdos/ls                           # compile + assemble -> bdos/ls.btap (no .genb, quiet compiler)
bcc bdos/ls                                       # same via the console command (`pip install -e .`), any directory
cd src/bc && python3 -m unittest discover -s tests -t . -p "*_tests.py"   # grammar and codegen tests
python3 scripts/code_size.py                      # code size of every program: Markdown table vs src/bc/code_size.csv
python3 scripts/code_size.py --check              # exit 1 if a program differs from its latest CSV row (the release-suite test runs this)
python3 scripts/code_size.py --record             # after an intended codegen change: append the changed rows to the CSV
```

`bcc` runs `winpty python` when `winpty` is on `PATH` (Git Bash) and `python3` otherwise.
Compiler errors go to stderr as `<file>: error: <message>` with exit code 1; see `bc_log.py`.

`src/bc/code_size.csv` is the committed code-size log: header `date,program,start,bytes,basm_sha`, append-only,
and the latest row per program is its expected state. `basm_sha` is a hash of the generated `.basm`, so a change of
the same size is caught too. The check is `scripts/tests/test_code_size.py` (release suite) and fails on any program
whose size or code differs from its latest row. When a codegen change is intended, run `--record` (it prints old -> new
sizes), review them, and commit the appended rows with the change. No golden `.basm` files are tracked.

The compiler and its tests run on Linux, macOS and Windows with Python >= 3.10 (tested on
3.10, 3.13 and 3.14); `parsy` is the only dependency. Internal compiler errors raise
`CompilerError` (defined in `bc_ast.py`). Output files (`.basm`, `.genb`) are written as UTF-8. They are build
outputs: ignored by git and never committed. Every `.basm` starts with `; generated by bc from <name>.b - do not edit`.
`bc.py` sets `sys.setrecursionlimit(2000)` because the parsy grammar recurses deeply.

## How it works

- `bc_log.py` is the compiler's only output channel: trace (stdout, `--verbose` only), the summary
  line (stdout) and errors/warnings (stderr). `bc.py` and `bc_ast.py` never call `print` directly.
- `bc.py preprocess()` handles `#include` (resolved relative to the **main** file's
  directory), `#define` (plain text replace, longer names first, applied inside strings and
  `asm` too), `#code` / `#heap` (module globals for the code and heap addresses), `#codelimit`
  (reset on every `preprocess()`, so it does not leak between compiles), and drops `//` lines.
- `bc_grammar.py` (parsy) builds the AST from `bc_ast.py`. Each node's `emit(context)`
  appends assembly text to `Context.basm`. `PROGRAM.emit` prepends the entry point; then the
  data segment and `bc_stdlib.py` (asm runtime, a format template with `{0}`/`{1}`
  placeholders) are appended.
- **Code model:**
  - an expression's result is in `csci`, and a binary operator's right operand in `dsdi`;
  - intermediate values go on the CPU stack;
  - variables live on a software stack at `sys_stackhead` (placed after the program image),
    accessed through the `stackvar*` runtime helpers at offsets relative to it;
  - `Scope` tracks those offsets;
  - a call pushes a scope (moving `sys_stackhead`), assigns the arguments as the callee's
    first locals, `cal`s the function, then pops the scope;
  - `CODE_BLOCK` doesn't open a scope, so locals must be unique within a function.
- Optimisations live in `EXPRESSION_BINARY.emit` / `logic()`:
  - a constant right operand of a commutative operator is loaded straight into `dsdi`
    (`context.hint_loaddsdi`);
  - comparisons with `0` are short-circuited.

  The `poc/bcc-opts*` branches contain earlier optimisation experiments.

## Rules

- Generated assembly must follow bc81asmc syntax: lowercase, fixed-width hex (`0x{:02x}` /
  `0x{:04x}`), one instruction per line.
- `bc_stdlib.py` routines call bcOS through `os_metacall` table indices. Those indices must
  match `os_metatab` in `src/bc81asmc/bcOS/bcos.basm`. The `.def var_promptbuf 0x0bcf` /
  `var_user_mem 0x0bcb` at the end of the runtime are stale bcOS 1.1 addresses and nothing
  references them. Don't use them; take the addresses from `os_vartab` instead.
- Changing the code model or the runtime changes every program. Afterwards, rebuild bdos
  and all programs (`./buildos && ./buildtools && ./buildapps && ./makedisc`), boot
  `os.bdd`, and smoke-test `ls`, `cat` and `texted`.
- An intended change to the generated code is recorded in `src/bc/code_size.csv` in the same commit
  (`python3 scripts/code_size.py --record`). The unit suite fails until it is.
- Language quirks to keep in mind, both when writing B and when changing the grammar:
  - comparisons bind looser than `&&`/`||`;
  - a unary operator applies to the whole rest of the expression;
  - `return` should be the last statement of a function (`bugs.txt`).
